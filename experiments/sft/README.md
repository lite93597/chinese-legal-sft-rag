# SFT：数据进入模型与实际训练过程

[实验总览](../README.md) · [数据层](../../data/README.md) · [RAG流程](../rag/README.md) · [评测结果](../evaluation/README.md)

模型实验标签为 `Qwen3.8-27B / legal-v4`。这是原项目使用的标签，不据此虚构公开模型仓库地址；本仓库当前没有发布基座或LoRA权重。

## 1. 使用哪些数据？

原划分为15,242条训练、1,923条验证样本，包括法律问答、抽取、摘要、规则适用、证据处理和多轮咨询。105条完整案例来自35个相关案例家族，已包含在上述总数中，不再额外相加。

15,143条训练和1,917条验证记录已有 `messages`；另99条训练/6条验证案例使用结构化问题、答案及 `context_documents`。通过仓库的 `training_messages()` 统一组装，不能因为没有 `messages` 就丢掉它们。完整案例及多轮示例见[数据示例](../../README.md#sft数据示例)。

## 2. 消息、Token与训练目标

实际流程：保留原划分 → 组装系统提示及所有对话轮次 → 将用户可见法源材料放入相应用户消息 → 使用对应Tokenizer和Chat Template编码 → 构造损失标签。

系统提示、用户问题、参考资料和历史对话提供上下文；仅各轮Assistant回答及相应结束标记参与损失，其余Token标签屏蔽为 `-100`。多轮数据监督全部Assistant轮次，而不是只截取最后一个回答。超过训练长度的记录不能静默裁切后冒充原样训练。

## 3. 实际LoRA配置

完整记录见 [config.json](config.json)，不是一个已经打包好训练入口的配置文件。

| 项目 | 本轮值 |
| --- | --- |
| 数值精度 | BF16 |
| LoRA | r=16、alpha=32、dropout=0.05 |
| 学习率 / warmup ratio | 2e-5 / 0.03 |
| 训练轮数 / 最大训练长度 | 1 epoch / 8192 Tokens |
| 单设备batch / 梯度累积 | 4 / 2 |
| 随机种子 | 42 |
| 长度分组 | 启用 |

目标层包括注意力投影 `q_proj/k_proj/v_proj/o_proj`、线性注意力投影 `in_proj_qkv/in_proj_z/in_proj_b/in_proj_a/out_proj` 与FFN投影 `gate_proj/up_proj/down_proj`。它不是只微调4个注意力层的旧2B配置。

## 4. 已完成的训练与产物

原正式训练完成1,906个优化步、1 epoch。训练完成记录的平均 `train_loss` 为0.5874833，训练运行时间8,087.2526秒（约134.8分钟）。这是训练统计，不是验证集loss或法律正确率，不能用它代替消融测评。

正式LoRA文件大小467,047,680字节，包含992个适配器张量，对应496组LoRA A/B参数。本仓库当前只发布 [training_summary.json](training_summary.json) 中的摘要，不包含这份权重。将适配器安全合并后用于本轮SFT/SFT+RAG推理；合并不是重新训练。

## 5. 后续加入代码或模型时

训练源码和运行依赖放在本目录，继续引用根目录 `data/sft/`；模型发布信息应给出真实基座标识、适配器配置、下载地址和许可。不能仅靠当前JSON就声称其他硬件、模型或Tokenizer一定能重现本轮结果。
